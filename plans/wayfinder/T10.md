# 连接韧性 — 嵌套父子进程探测

## Question

强化嵌套父子进程探测，防 `python -m trading` 自带系统 Python310 子进程双起抢同一 sid（T4 根因 B 层）。候选手段：psutil 祖先链探测 / PID 文件锁 / 启动期单例守卫。

**前置实证（必须先做）**：嵌套父子在当前 `schtasks → start_server.bat → python -m trading` 链路是否真发生（T4 待实证 #2/#6）——若 C-5/C-7 进程模型改造后已不发生，本工单**降级为防御性探测或直接关闭**。

## Context

毕业自 [T4](T4.md)。memory（qmt-connect-1-rootcause）已部分修：双进程树杀 + venv 主独占 session。本工单是探测强化防再生。T4 标"部分修，嵌套父子待实证"。

## Notes

- 对应 T4 T-conn-2。**先实证是否再生再决定投入**——若已不发生，避免过度设计（CLAUDE.md 反过度设计）。

## Resolution

**实证结论（2026-08-15 12:47 进程快照，只读 wmic/Get-CimInstance，live 引擎运行中）**：
嵌套父子**真实发生**，但为单条进程树的「venv 启动器」形态，**非两条独立树双起抢 sid**：

- PID 1456 `E:\quanter\.venv310\Scripts\python.exe -m trading`（launcher，树根，父 26716 已退出的 schtasks 链）
- PID 11548 `C:\...\Python310\python.exe -m trading`（base 解释器，**父=1456，同秒创建 12:47:51，持 :8000 即 live 引擎本体**）
- PID 28612 venv python spawn worker（父=11548，12:48:53，cmdline=spawn_main 不含 -m trading）
- 另见孤儿 spawn worker PID 20984（父 22048 已死，前日 18:52 遗留，不匹配引擎 cmdline，与本工单无关）

处置（按预案「发现嵌套→补递归祖先链去重+测试」）：

1. `ops/process_topology.py` `engine_processes` 去重升级为**递归祖先链**（`_drop_engine_descendants`
   纯函数）：CIM 查询改取全进程表建 pid→ppid 图，任一祖先是引擎 pid 即判后代丢弃。
   旧「直接父 ∈ 引擎集合」一级判据对「经非匹配中间进程（spawn worker / cmd.exe）挂下来的
   -m trading 孙辈」漏网（audit 误计多引擎 / stop 树杀漏孙辈）；两条独立树（真双起）仍都
   保留——探测不掩盖双起事实。含 PID 复用环 seen 防死循环。
2. 测试：`tests/ops/test_process_topology.py` 6 用例回放快照形态（launcher→base 两级、
   spawn worker 孙辈、非 python 中间进程、双独立树保留、环终止×2）+ `tests/test_audit_ssot.py`
   同步 mock 迁移并加孙辈穿透用例。
3. **不引入** psutil 祖先链 / PID 文件锁 / 启动期单例守卫等新机制（候选手段过度设计）：
   实证威胁模型是「同树 cmdline 双匹配」而非「双起」，taskkill /T 树杀根即全清。
