# 架构演进期的验证与回归防护策略

## Question

架构演进期（engine 拆分 / 适配层引入 / 三维扩展）如何**验证不破坏现有行为**？决策点：

1. **现有基线够不够**：golden baseline + e2e_long_cycle（已 PASS 4.9min，1200 passed）能否覆盖 engine 拆分前后的行为等价验证？
2. **待补测试类型**：是否需要补充——契约测试（适配层 conformance，确保每个策略/资产/账户/经纪商实现满足接口契约）、多策略/多账户隔离测试（T3 的 adversarial 场景）、engine 拆分前后双跑对比（行为等价证明）。
3. **回归防护策略**：每次重构的最小测试集 + CI gate；e2e_long_cycle 是否纳入每次重构必跑。
4. **性能回归基线**：回测速度、信号扫描耗时、tick 处理——是否建立性能基线防退化。

## Context

- 横切决策，影响所有重构工单（T1/T2/T3 尤甚）。
- memory：e2e_long_cycle_status（C1-C7 长周期 E2E，full_run PASS 4.9min）、golden baseline 刷新记录。
- 演进期频繁重构心脏，无回归防护 = 灾难。CLAUDE.md "数据质量与鲁棒性检查" 要求。

## Resolution

**决策已落 ADR-09（2026-08-12，W0 护栏批，commit `82a614a8`）**：[docs/architecture/09-t7-validation-strategy.md](../../docs/architecture/09-t7-validation-strategy.md)——四决策点全部定稿：① 现有基线（golden baseline + e2e_long_cycle）不够 → 增补四层验证 L1 单元 / L2 适配层 Protocol conformance / L3 e2e（每波次合并前必跑）/ L4 双跑对比（重构行为等价证明）；② 待补测试类型 = L2 契约 + L4 双跑（已列何时跑）；③ 回归防护 = CI 全量绿门（防「既有红」积累）+ 每波次独立 PR 未达验证门不合并；④ 性能基线 = 回测速度/扫描耗时/tick 延迟首次记录 + CI 10% 退化软拦（告警 + 人审）。

**已实际执行佐证**：T1（engine 拆分）靠 golden baseline + e2e 验等价（功臣）；2026-08-15 技术债波次 Wave E 门兑现 L3（26 passed）+ L4 双跑零差异 + perf +1.9% ≪ 10% 阈值——四层验证不再纸面。
