## Question

`trading/engine.py`（3437 行 god module）应按什么**主维度**切分为清晰子模块？候选：

1. **按职责**——调度编排 / 订单状态机 / 风控 / 对账 / 数据准备；
2. **按生命周期**——pre_open / intraday / eod / post_close；
3. **按领域**——订单 / 计划 / 持仓 / 行情。

用 **stub prototype** 对比 2-3 种切法在以下维度的表现，**选定主切分维度并给出目标模块树**：

- 可测试性（每个子模块能否独立测试，依赖注入清晰度）；
- 未来可插拔适配层（T2）的友好度——切分后的"内核"边界是否自然适配策略/资产/账户/经纪商接入；
- 与既有 C5（进程模型单例）/ C6（时间统一 clock）/ C4（错误分级 _CriticalHalt）的兼容性；
- 与 strangler fig 替换路径的兼容（即便演进优先，逐步替换仍最安全）。
