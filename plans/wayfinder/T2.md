# 可插拔适配层接口契约

## Question

"可编排内核 + 可插拔适配层"的四个适配层——**策略 / 资产 / 账户 / 经纪商**——的接口契约如何定义？每个适配层需敲定：

- **职责边界**——每个适配层负责什么、不负责什么；
- **数据契约**——输入输出（信号 / 行情 / 订单 / 成交 / 持仓的数据结构）；
- **注册与发现机制**——声明式配置？注册表？插件入口；
- **配置驱动方式**——多策略多账户如何用配置组合而非改代码；
- **生命周期钩子**——pre_open/on_signal/on_fill/eod 等钩子点。

用 **stub prototype** 验证"单策略单资产单账户（现状颈线法/QMT/A股/单账户）→ 多策略多资产多账户"的接入路径，确认接口可行且**不破坏现有路径**（现有颈线法必须能作为"策略适配层"的第一个实现平滑迁入）。
