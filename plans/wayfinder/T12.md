# data 活债排查 — a_shares_daily.parquet 单日真因（P0）

## Question

当前工作区 `data_lake/a_shares_daily.parquet` 仅含**单日 3200 行**（git LFS 入库，未提交，见 `git status`），与生产期望的全量历史不符。**这是 P0 活数据债**——[T5](T5.md) 实证：`find_gaps` 在单日湖上返回空，导致**三层完整性 gate（freshness / scan_integrity / filter_universe_by_continuity）全部静默失效**，历史缺口永不被发现。

必须先实证真因：

1. 是 **git LFS 指针未拉取**（smudge 失败）致本地仅指针/单日？
2. 还是 **全量重建链路漏掉**（`sync_daily_incremental` 只追加单日）？
3. 还是 **历史 LFS 对象被清理/未推全**？

再定修复方向（LFS 配置修复 / 全量重建 / sync 链路修复）。

## Resolution（research · closed 2026-08-08）

**真因（实证，全部有日志/代码佐证）**：

1. **直接动作**：2026-08-07 **18:11:59** engine 重启触发 `presentation.server.main` 启动同步 sweep，对 `daily` 调 `data/tools/sync_tushare.py daily`（`config/registry.py:49` 指定的 daily 官方脚本，**非增量**）。**18:12:54** 该脚本报"成功"，但在 SOCKS 代理异常环境下只拿到 **2026-07-24 单日残片**，通用同步器**无写入前历史数据量守卫**，直接 `to_parquet` 覆盖 → **a_shares_daily 1020万行/454MB → 3200行/157KB**。证据：`logs/quanter.log:51482/51529` + `logs/data_pipeline.log:84-85` + 工作区文件 shape (3200,7) 含 `ts_code` 列（匹配通用同步器 `set_index` 不 drop 形态）。

2. **环境根因**：`.venv310` 缺 PySocks（`requests[socks]`），却配了 SOCKS 代理 → 所有经 requests 的 tushare 调用抛 `InvalidSchema: Missing dependencies for SOCKS support.`（`data_pipeline.log:47/78/140`）。

3. **架构根因（daily 双轨）**：daily 有两个写入口——
   - ✅ `sync_daily_incremental.py`（`data_pipeline` schtasks 路径，增量 append + 除权重算 + backscan，**正确**）；
   - ❌ `sync_tushare.py daily`（`data_service` sweep 路径，通用同步器全量重建，**无增量语义、无写入守卫**）。
   `registry.py:49` 把 daily 的 script 标为 `sync_tushare.py`，使 data_service 启动 sweep 走全量重建路径。正是 [T5](T5.md) 调研预警的"daily 双轨"。

4. **gate 根因（为何 ~14 小时未被发现）**：`freshness.py` 只校验"最新日 vs 期望日"，**不检测历史行数骤降**；`scan_integrity`/`repair_gaps` 无调度。8/7 18:27 ~ 8/8 11:18 系统反复告警"daily 陈旧"并重采（仍 SOCKS 失败），**无人发现 1020万→3200 的历史抹除**；`filter_universe_by_continuity` 在单日湖 fail-open 跳过所有标的（交易侧静默）。

**好消息**：a_shares_daily 是 LFS 跟踪，HEAD 有完整 454MB 对象（oid `d96839ea...`，1020万行 / 2016-07-06~2026-08-04 / 2448 天）——**全量历史可一键恢复，未永久丢失**。

**修复方向**：
- **立即恢复（P0 运维，毕业为 [T14](T14.md)）**：① `pip install pysocks`（或改 HTTPS 代理）修环境；② `git checkout HEAD -- data_lake/a_shares_daily.parquet` 恢复 1020万行全量；③ 跑 `sync_daily_incremental.py` 补到今天。
- **治本防御（归入 [T13](T13.md)，置顶优先）**：① daily 双轨收口（registry 让 daily 唯一入口 = sync_daily_incremental，或给通用同步器加"增量模式 + 写入守卫"）；② 所有 lake 写入加"写入前历史行数守卫"（新行数 < 现有 90% 拒写 + CRITICAL 告警）；③ freshness 加"历史行数骤降"检测维度。
