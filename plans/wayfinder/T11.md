# 连接韧性 — 启动期 connect 失败重试

## Question

启动期 `connect` 返回 -1（客户端就绪判定通过但连接失败）场景加**有限重试**。T4 标可作 T9 子任务——与主动探针 watchdog 配套（探针发现僵死 → 触发重连重试）。需定：重试次数、退避策略、熔断阈值（避免 -1 死循环雪崩）。

## Context

毕业自 [T4](T4.md)（方向 C）。低优先，依赖 [T9](T9.md)（探针）落地后配套实现。

## Notes

- 对应 T4 T-conn-3。
- CLAUDE.md 风控：重试必须带熔断 + 指数退避，记录每次 -1 的 status_msg（memory: 688160 拒因黑盒修复经验），避免盲重试。

## Resolution

**观测补齐完成（2026-08-15）**：`broker/qmt.py` connect attempt 循环内，**每次**返 -1 即留痕
`logger.warning("connect -1 sid=%s rc=%s msg=%s", ...)`——rc 打字面量（评审修复：-1 非
委托状态码，硬塞 `_map_qmt_status` 会落默认分支打成误导性 `status=SUBMITTED`，rc 与
OrderState 两套语义不混叠），msg 记 attempt 轮次与 -1 物理含义
（死进程残留会话/sid 被占，柜台无文本回报），兑现 Notes「记录每次 -1 的 status_msg」防
688160 式拒因黑盒。

**重试语义保持 G8 形态不再改**：两轮 -1 清理重试 + G8 客户端可服务闸（未就绪跳过轮换直进
L3）+ L2 sid 自动轮换 + L3 fail-closed 的次数/顺序零变更（周一实战前不动行为）。Notes 中
「有限重试/指数退避/熔断阈值」的增项不再展开——现行 L1→L2→L3 链路已构成带熔断（lockdown
+ health_guard 60s 轮询自愈）的完整重试形态，叠加退避属过度设计。
