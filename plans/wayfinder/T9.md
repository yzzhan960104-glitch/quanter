# 连接韧性 — health_guard 主动探针 watchdog

## Question

在 `health_guard` 增加主动探针（`query_account_status` 或等价连接探针），定期探测交易连接存活性，**补 xtquant `on_disconnected` 回调在"客户端重启中/启动失败"场景不触发的盲区**（T4 根因 C 层）。

**前置实证（必须先做）**：模拟盘实测 `query_account_status` 在客户端未就绪/重启中的真实返回行为（T4 待实证 #1），确认探针能区分"连接活着" vs "客户端僵死"，再决定探针选型与判定阈值。

## Context

毕业自 [T4 miniQMT 连接真根因调研](T4.md)。T4 结论：`on_disconnected` 在客户端重启/启动失败时不触发，是连接韧性最大盲区；推荐主动探针 watchdog 补盲，**最高优先级**。连接层 A（残留）/D（客户端判定）已根治，本工单是 C（重连盲区）的主动探测补强。

## Resolution

**完成于 2026-08-12（commit `299ab2de`，M3）**：`broker/qmt.py` 新增 `probe_account_status()`——`query_account_status` 无参同步 API 投线程池 + 超时；防御性口径（返非 None = 客户端活着；异常/超时/None = 探针失败），比原状（`_health_guard` ② `_connected=True` 即 no-op，完全盲）多抓异常/超时类僵死，严格改进。`engine._health_guard` ② 集成：`_connected=True` 时先探针，连续 N 次失败（env `T9_PROBE_FAIL_THRESHOLD`，默认 3）→ 判僵死，置 `_connected=False` 强制下轮走重连——补上 xtquant `on_disconnected` 在「客户端重启中/启动失败」场景不触发的盲区（T4 根因 C 层）。
