## Resolution（research）

- 产出：`research/T5-data-integrity.md`
- gist：**最关键缺口** —— 生产数据链 supervisor（`ops/data_pipeline.py`）的完整性 gate 是 `data/freshness.py`，它**只校验「最新日期=期望交易日」（实时性）**，完全不校验历史连续性/停牌/复权；真正能扫历史缺口的 `scan_integrity.py` + `repair_gaps.py` 是**孤立 CLI，无任何调度触发**。结果：lake 历史段漏采（300214.SZ 那种）只能在信号产出最后一道 `filter_universe_by_continuity`（fail-open 窗口 gate）被「跳过该标的」被动兜底，**缺口本身永远不被发现、不被补采**。叠加活数据债（当前工作区 `a_shares_daily.parquet` 仅单日 3200 行，git LFS 入库，待实证真因），`find_gaps` 在单日湖上返回空，三层 gate 全部静默失效。
- **根治核心**：① 把 `scan_integrity` 升级为生产链路强制 gate（接进 `data_pipeline` T1/T2 + 每周全扫）；② 把 `repair_gaps` 升级为自动补采触发（scan FAIL → 自动 repair，受配额/熔断守卫）；③ 完整性维度收敛到 `data/integrity.py`（新增 freshness 没覆盖的 D5 复权一致性 / D6 列完整性 / D7 跨湖时区 / D9 行数阈值告警）；④ daily 湖双轨收口（从 `TUSHARE_DATASETS` 删 `"daily"` key，唯一写入口 = sync_daily_incremental）；⑤ repair_gaps 裸调 pro 改走 `_fetch_with_guard`（限频裸奔修复）。
- **毕业建议**：**需新建 1 个 data 重构工单**（补进 wayfinder MAP）。工单 Question 草稿见 `research/T5-data-integrity.md` §8（7 项：G6 活债排查 P0 / scan+repair 自动化 / 生产 gate 维度扩展 / daily 双轨收口 / 限频裸奔修复 / D5+D7+D9 新维度 / C3 除权基准 follow-up）。建议先做 G6 活债排查（P0，LFS 或全量重建），再做 scan/repair 自动化（解除手动 CLI 依赖）。
- 附带发现（文档债，非本工单 scope）：`docs/data_pool.md` 严重过时（仍引 AKShare/JQData/dragon_list/sector/north_flow，全已退役），应更新或归档。`docs/data-source-of-truth.md` 只覆盖交易侧 SSoT，不覆盖 data 湖，data 湖缺对应 SSoT 文档。
