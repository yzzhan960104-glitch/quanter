# tushare 代理 env 根治（SOCKS5 5001 失联）

## Question

quanter 运行环境配了 `ALL_PROXY=socks5://127.0.0.1:5001`，但该 SOCKS5 代理服务自 8/7 起失联（`[WinError 10061] 端口拒绝`），导致所有 tushare 调用（`trade_cal`/`daily`/`adj_factor`）失败。pysocks 已补齐（T14），但代理端口仍不通。生产 schtasks（`data_pipeline` → `sync_daily_incremental`）环境仍有此 `ALL_PROXY`，**下次调度会再失败**；且若再触发 `data_service` 启动 sweep 调 `sync_tushare.py daily`，在 [T13](T13.md) 写入守卫未做前**可能再次覆盖 a_shares_daily**。

根治方向决策（三选一，需用户输入"SOCKS 代理是否 quanter 之外的必需服务"）：

- **A. 启动 SOCKS 代理服务**：确认 `127.0.0.1:5001` 是什么代理软件（v2ray/clash/...），恢复它。前提：代理是其他服务（境外访问？）必需。
- **B. 从 quanter 运行环境移除 ALL_PROXY**（CLAUDE.md 极简倾向）：tushare API（`api.waditu.com`）国内直连已验证可行（[T14](T14.md) 增量成功）；改 `.env` / schtasks bat（`run_data_pipeline.bat` 等）/ 系统环境变量，让 quanter 进程不继承 `ALL_PROXY`。前提：quanter 不需代理访问 tushare。
- **C. 代码层绕过**：tushare 调用设 `NO_PROXY=api.waditu.com,api.tushare.pro` 或 `trust_env=False`。改代码（`data/_tushare_compat.py` / `tushare_sync.py`）—— 与"演进优先不改代码"冲突，最不偏好。

## Context

毕业自 [T14](T14.md)。T14 已临时绕过（`unset ALL_PROXY`）完成 data 恢复，但**生产环境未根治**。这是 T14 的遗留 P0——比 data 恢复更隐蔽（data 恢复了，但下次 sync 又会坏）。

## Notes

- 关联 [T13](T13.md)：即使代理修好，T13 的"写入守卫 + 双轨收口"仍是防覆盖根本；T15 是防 sync 失败。**两者都须做**。
- 决策依赖用户事实：**SOCKS 代理（5001）到底服务于什么？** 若只是历史遗留（quanter 不需要），选 B 最简；若其他服务（如 discovery/backtest 访问境外数据？）必需，选 A 或 C。

## Resolution（grilling+task · closed 2026-08-08）

**决策**：**B — 从 quanter 运行环境移除 ALL_PROXY**（tushare 国内直连已 [T14](T14.md) 验证可行，quanter 不需代理）。

**落地**：
- 来源定位：ALL_PROXY 仅在 **Windows User 环境变量**（`socks5://127.0.0.1:5001`）；`.env` / `scripts/*.bat` / shell profile 均无。
- `[Environment]::SetEnvironmentVariable("ALL_PROXY",$null,"User")` 删除；同时清 User 级 HTTP_PROXY/HTTPS_PROXY 残留。
- **权威验证**：`GetEnvironmentVariable('ALL_PROXY','User')`=[] + `reg query HKCU\Environment /v ALL_PROXY`=找不到 → **注册表已删 → schtasks 新进程（Task Scheduler 直接启动，读 User+Machine 注册表合成 env）不再继承 ALL_PROXY**。

**效果**：下次 schtasks `data_pipeline` → `sync_daily_incremental` 新进程链无 ALL_PROXY → requests 直连 tushare → 不再 `InvalidSchema`/`ConnectionError`。

**运维提示**：
- 当前已运行进程（本 session Bash / engine）仍持陈旧 ALL_PROXY，**重启后读新 env**。
- 若 5001 代理软件（v2ray/clash 等）重启且开"系统代理"，会再写 ALL_PROXY → 需在**代理软件层关闭"设系统代理"**，或接受复发后重删。
- 仅清了 quanter 用户 env；其他程序需代理应单独配，不污染系统 User env。

**根治闭环**：[T12](T12.md)（排查）→ [T14](T14.md)（恢复 data）→ **T15（修环境）** = data 活债完整闭环。剩余治本（写入守卫 + 双轨收口 + scan/repair 自动化）归 [T13](T13.md)。
