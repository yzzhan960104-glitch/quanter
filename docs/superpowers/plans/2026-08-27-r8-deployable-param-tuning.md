# R8 · 部署口径参数重优 · 8 小时受控方案（2026-08-27 设计稿）

> 用户指令：设计一个运行 8 小时的参数方向调优方案。
> 定位：**「冻结不搜索」解冻条款首次合法触发**——R7c 发现排队纪律=模拟器结构
> 变化（先知 exit_date 序 vs 可部署随机序），全部历史参数结论（R6-8/B3 冠军、
> 11 活跃/10 冻结维度划分、不敏感判定）均在先知口径下建立；**部署口径的参数
> 响应面从未被搜索**。本跑是这块处女地的首次侦察，不是对已收官参数战役的重跑。

## 一、为什么两个口径的最优参数应该不同（机理先行的方向假设）

- **先知调度**（exit_date 序）从 80+/日候选中挑最快了结者（taken 平均持有
  1.8 天），组合收益≈精选快速赢家的复利机 → 奖励**深目标/长持有**参数
  （tp2 远、max_holding 松），因为赢家反正会被挑出来；
- **可部署调度**（随机序中位，taken 平均 ~12 天持有、外层仅 ~60 笔）平均吃
  信号，4 槽是硬约束 → **周转率成为一阶变量**：更快的了结（紧 tp2/短持有/
  快 trailing）用单笔 pnl 换槽位周转，理论上应被结构性加权。
- 方向性预测（预登记，供事后对照）：**max_holding / tp_h_mult / trailing 三件
  / tp_adapt（B3 轴）族在部署口径下的最优档位应系统性偏紧**；若 8 小时跑完
  这四族一档未动，本身即是「部署口径参数不敏感」的战役级答案。

## 二、目标函数与口径纪律

- **优化目标（循环内）**：`inner 2021-2024` 段、冻结 PM（4×7.5% 整手+min5+
  freeze_pending@100w）、`queue_order=random` **K=5 种子的配对中位 ann**。
  用 inner 训练、**outer 2025-26 作终审 holdout**——保持战役的 inner/outer
  信息隔离纪律（部署口径下 outer 样本太小 ~25-60 taken，不进搜索只进终审）。
- **对照基线**：B3 ACTIVE（neckline_r610_b3_20260826）同口径配对值（启动时
  一次算定并缓存，全程不复扫）。当前参照：全期 deployable 中位 +4.9%。
- **oracle 伴跑**：每次采纳时同报 oracle 口径读数（免费，一次调用）——连续性
  锚不丢弃，且观察两口径的排序是否漂移（这本身是研究产出）。

## 三、噪声控制（本跑成败的核心工程）

部署口径天然高噪（21 种子外层极差 −12.9%~+35.2%），无噪声设计=自欺。四件套：

1. **共同随机数（CRN）**：候选与基线用**同一份种子列表**配对评估（循环内
   seeds=[0..4]，终审 [0..20]），取**配对差值**的中位——同种子下两参数集共享
   排序路径，差值的方差远小于两个独立中位数之差；
2. **采纳阈值**：配对中位 Δann ≥ **+2pp**（inner deployable）才进闸——低于
   噪声地板的改进不追；
3. **符号一致性**：≥4/5 种子同向（终审 ≥15/21）——中位数被单种子拉动不算数；
4. **换手守卫**：deployable n_taken 变化 ≥ −30%——吞吐塌了的中位提升视为
   假信号（参数砍信号量在部署口径下比先知口径更致命）。

## 四、预登记采纳闸（六条，先于发射写死在循环代码）

1. **G1 主闸**：inner deployable 配对中位 Δann ≥ +2pp（K=5）；
2. **G2 符号一致**：≥4/5 种子同向；
3. **G3 逐年不塌**：inner 各年（21-24）deployable 中位无恶化 >10pp（年样本小，
   阈值放宽；终审对 25-26 外层也查同款）；
4. **G4 换手守卫**：n_taken ≥ 基线 70%；
5. **G5 oracle 护栏**：oracle 全期 ann Δ ≥ −5pp（不摧毁内部连续性口径的
   读数——它是全部历史 A/B 的锚）；
6. **G6 红线**：C2 内核零触碰 / ADR-16 池子侧不进任何参数路径 / 闸不改中途。

终审（Phase C）附加：outer 25-26 holdout 的 K=21 配对中位 Δ ≥ 0 且 ≥15/21
种子同向——**外层翻号即整体否决**（与 R6 系「G4 外层一票否决」同纪律）。

## 六、工程复用与要点

- 骨架：`diag/r6_10_b3_loop.py` 范式（state.json 断点续跑 / 贪心栈 / 预登记闸
  / FINAL+DRAFT 自动化），目标函数换成 CRN 配对 deployable 中位；
- 评估管线：`run_full_scan`（R6-1 识别缓存跨同 id_cfg 变体复用——exec 维
  变体 ~13-18s，id 维全识别 ~95-150s）+ `portfolio_metrics(queue_order=
  "random", queue_seed=s)`（昨日已入库）；
- 基线缓存：incumbent 的 filled 列表与逐种子指标缓存进 state，比较时只扫候选；
- 已知规避：不用 TPE（子进程 OverflowError inf→int 待修，贪心不受影响）；
- 双轨/引擎零干扰：只读湖、内存驻留、不动 trading/。

## 七、期望管理与裁决框架

- **这是侦察不是收割**：部署口径基线只有 ~+4.9%（全期中位），样本薄噪声高，
  8 小时的合理产出上限是「找到 1-3 个方向正确的吞吐族采纳 + 首张部署口径
  参数响应地图」；**null result（零采纳存活）同样是战役级交付**（=部署口径
  参数也不敏感，剩余杠杆确认只在 H-R7d 执行面）；
- 与 H-R7d 的关系：互补不互斥——本跑若证实吞吐维（mh/tp/trailing）主导，
  正是 H-R7d「预测快速了结优先进场」的参数侧印证；若零采纳，H-R7d 的相对
  优先级进一步升高；
- 过闸后的晋级仍走 fail-closed 纪律：DRAFT 物化 + 用户显式 promote 才换
  ACTIVE，双轨对照自然承接（且实盘将直接检验部署口径读数）。
